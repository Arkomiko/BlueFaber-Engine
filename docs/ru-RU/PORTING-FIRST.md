Перенос между версиями Minecraft — главный сценарий BlueFaber. Перенос отдельной механики прогоняется до расширения холста и пакетов контента. Каждая следующая цель добавляет один новый вид различия, а обратное направление получает самостоятельные правила и испытания.

## Что считается переносом

| Результат | Свидетельство |
| --- | --- |
| Импортирован | Идентифицированы Minecraft, loader, классы, реестры, зависимости и сторона. Входной артефакт и его хеш сохранены. |
| Восстановлен | Рабочее пространство содержит читаемые исходники, ресурсы, манифест и решения о зависимостях. Пробелы перечислены по адресам. |
| Собран | Целевой независимый проект собирается в JAR с точными версиями JDK и зависимостей. |
| Работает | Целевая игра или сервер загружает JAR и воспроизводит принятые сценарии, в том числе после перезапуска, когда затронуто сохранение. |
| Частичный результат | Для изменённого или отсутствующего поведения известны исходный узел, причина, решение и тест, который ещё требуется. |

Гарантия распространяется на проверенные входы и заявленные возможности. Каждый входной JAR должен получить понятное состояние даже при неизвестном загрузчике, отсутствующей зависимости, неполном classpath, обфускации, нативном или динамически загружаемом коде. Классам, которые нельзя восстановить в граф, назначается происхождение и дальнейшее действие. Новый JAR выпускается только для полученного профиля и выбранных проверок.

## Порядок для одного разработчика

1. **Собрать корпус и закрепить среды.** Собственный минимальный Fabric JAR с рецептом и предметной моделью, независимый Paper-плагин с ванильным рецептом, отрицательный пример с клиентским блоком для серверного профиля. Сохранить эталонные исходники и хеши отдельно от входного JAR. Картировать, какие инструменты восстанавливают сигнатуры, ресурсы и сборку. [Java и восстановление](JAVA-RECOVERY.md)
2. **Провести ранний эксперимент с версиями.** Кандидаты — Fabric 1.21.1 и 1.21.4. Исходный JAR открыть без исходников. Проверить независимую сборку исходной версии, затем перенести рецепт и модель между версиями. Обратный прогон начинается с отдельного JAR целевого поколения. При недоступном эквиваленте фиксируется отрицательный тест. На этом этапе достаточно командного стенда и артефактов приёмки.
3. **Показать ту же операцию на холсте.** Импорт рецепта, источник узла, изменение результата, предпросмотр миграции, сборка и повтор опыта. Проверить сохранение неизвестных полей и внешнего Java, стабильность ID и откат. [Архитектура редактора](ARCHITECTURE.md)
4. **Добавить трансформации и загрузчики.** Сначала методы, завязанные на refmap и точку инъекции. Сверить точное совпадение, несовпадение, неоднозначность и изменение поведения. Затем Forge ↔ NeoForge, Forge ↔ Fabric и NeoForge ↔ Fabric на общей версии. Результаты нативной пересборки и работы через слой совместимости получать отдельными испытаниями. [Профили и Mixin](PORTING.md)
5. **Проверить Bukkit, Spigot и Paper.** Для каждого сервера провести обновление и обратный порт. Проверить все шесть направлений между этими платформами на общей версии. Для каждой пары мод ↔ серверный плагин завести двустороннюю запись с совместимой серверной операцией и отдельным ограничением по реестру, сети или клиенту. Профиль привязать к фактическому дистрибутиву.
6. **Увеличить масштаб.** Проверить историю Forge, подходящие исторические поколения Fabric и Bukkit, собственные контентные пакеты, затем крупный внешний корпус. В каждом профиле закрепить версию игры, Java, загрузчика, mappings, зависимости, стороны, условия распространения и область ожидаемых изменений сохранений.

## Долгосрочные сценарии

- **IndustrialCraft 2 и Thaumcraft → более новый Fabric.** Кандидаты для проверки исторического Forge, старых классов, сохранений, машин или магических систем. До выбора закрепить точный выпуск мода, права на использование, зависимости и наблюдаемое поведение. При закрытом исходном материале публичная задача может проверять собственную изолированную фикстуру того же технического класса. [Страница Thaumcraft](https://www.curseforge.com/minecraft/mc-mods/thaumcraft)
- **Affinity → NeoForge.** Кандидат на проверку современного Fabric-мода с зависимостями и клиентскими системами. Первый сценарий выбирает одну механику и сравнивает ее запуски на одной версии Minecraft. [Исходники Affinity](https://github.com/wisp-forest/affinity)
- **Moldonyan Industry → NeoForge.** Страница автора указывает выпуск 1.0.0 для Fabric 26.2, Java 25, Fabric API и лицензию MIT. Для пробы предстоит закрепить файл и хеш, проверить лицензию ресурсов и доступность NeoForge на общей версии. Кандидат на первую механику — один машинный рецепт с сохранением состояния. [Страница автора](https://www.curseforge.com/minecraft/mc-mods/moldonyan-industry)
