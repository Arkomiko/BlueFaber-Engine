## Очередь для одного разработчика

| Порядок | Задачи и результат |
| --- | --- |
| 1. Стенд | [BFE-0002](https://github.com/Arkomiko/BlueFaber-Engine/issues/2), [BFE-0003](https://github.com/Arkomiko/BlueFaber-Engine/issues/3), [BFE-0005](https://github.com/Arkomiko/BlueFaber-Engine/issues/5). Закрепить Java, Fabric, контрольные суммы и воспроизводимый запуск. |
| 2. Независимый эталон | [BFE-0012](https://github.com/Arkomiko/BlueFaber-Engine/issues/12), [BFE-1001](https://github.com/Arkomiko/BlueFaber-Engine/issues/1002). Вручную воспроизвести рецепт и модель на версиях-кандидатах в обе стороны. |
| 3. Восстановление | [BFE-0028](https://github.com/Arkomiko/BlueFaber-Engine/issues/28), [BFE-0029](https://github.com/Arkomiko/BlueFaber-Engine/issues/29), [BFE-0031](https://github.com/Arkomiko/BlueFaber-Engine/issues/31), [BFE-0036](https://github.com/Arkomiko/BlueFaber-Engine/issues/36). Сравнить выход декомпиляторов с исходным JAR, собрать тот же профиль. |
| 4. Узел и целевой JAR | [BFE-0114](https://github.com/Arkomiko/BlueFaber-Engine/issues/114), [BFE-0447](https://github.com/Arkomiko/BlueFaber-Engine/issues/447), [BFE-1002](https://github.com/Arkomiko/BlueFaber-Engine/issues/1003). Показать источник рецепта, изменить его и повторить игровой сценарий в обе стороны. |
| 5. Холст и пакеты | [BFE-0045](https://github.com/Arkomiko/BlueFaber-Engine/issues/45), [BFE-0165](https://github.com/Arkomiko/BlueFaber-Engine/issues/165), [BFE-1003](https://github.com/Arkomiko/BlueFaber-Engine/issues/1004). Выбрать и переиспользовать готовые компоненты редактора, проверить редактируемость и независимость копий пакетов. |
| 6. Расширение маршрутов | [BFE-0749](https://github.com/Arkomiko/BlueFaber-Engine/issues/750), [BFE-1019](https://github.com/Arkomiko/BlueFaber-Engine/issues/1020), [BFE-0993](https://github.com/Arkomiko/BlueFaber-Engine/issues/994). На новых профилях раздельно фиксировать перенос, ограничения и доказательства. |

Выберите одну готовую задачу. Условия начала и критерии выхода указаны в issue. Смежные проверки помогают выбрать минимальный набор для сценария. Записывайте наблюдение и версию среды там, где исполнялась проверка. Статус профиля меняется после прохождения отдельного маршрута в игре.

## Исправленные несостыковки

| Наблюдение | Что изменилось |
| --- | --- |
| В части задач продолжался сценарий выдачи стартового набора | Эталон, генерация, импорт и версионные испытания переведены на рецепт, модели, BLUSMOR и независимые серверные операции. События входа и PDC остаются самостоятельными проверками соответствующих API. |
| Задача создания примера в редакторе смешивалась с портированием существующего JAR | Сборка базового графа из пустого проекта описана в BFE-0226. Импорт независимого JAR описан в BFE-0447. Двусторонний сквозной перенос проверяется в BFE-1002. |
| Ранее первые результаты переноса появлялись в поздней вехе | BFE-1001 выносит пробу двух версий в P00. BFE-1002 проводит узкий маршрут после импорта и до полной библиотеки версионных правил. |
| Сравнивались результаты контентного Fabric-мода и обычного Paper-плагина | Для Paper предусмотрены отдельная положительная проверка ванильного рецепта и отрицательный тест недоступной регистрации. Каждый реальный сервер сохраняется в доказательствах. |
| Шаблон сводился к небольшому примеру руды | У BLUSTREE и BLUSMOR появились задачи по редактируемым подграфам, глубокой вставке, отдельным механикам и переносу. Базовый граф руды сохранился как отдельная ступень. |
| В списке обратной совместимости серверных платформ повторялось обновление | Для Bukkit, Spigot и Paper учитываются две стрелки версии. Отдельно учитываются смена серверной платформы и переходы между модами и плагинами. |
| Номер issue расходится с кодом задачи | Код BFE остаётся стабильным. Прямые ссылки ведут по номеру GitHub из проверенной карты. BFE-1022 отслеживает автоматическую проверку этой карты. |

У исходных 1 000 задач проверены уникальность кодов, последовательность, вехи, ссылки вида BFE и уникальность нормализованных заголовков и наборов критериев. Перепроверены близкие формулировки. Противоположные стрелки, разные загрузчики и разные результаты испытаний оставлены самостоятельными задачами. Например Fabric → Forge и Forge → Fabric используют разные входы, зависимости и тесты.
